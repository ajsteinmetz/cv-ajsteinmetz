# AJ Steinmetz — Curriculum Vitae & Statements

This repository contains the academic portfolio of AJ Steinmetz, including:

- **Curriculum Vitae** (`cv_ajsteinmetz.tex`, `cv_ajsteinmetz.pdf`)
- **Research Statement** (`research_statements/rs_ajsteinmetz.tex` plus figures)
- **Teaching Statement** (`teaching_statements/ts_ajsteinmetz.tex`)

It is also the **single source of truth** for publications, talks, teaching, and other CV data shown on the [website](https://github.com/ajsteinmetz/ajsteinmetz.github.io) and the [GitHub profile README](https://github.com/ajsteinmetz/ajsteinmetz).

---

## Updating the CV, website, and profile

1. Edit the relevant file in `data/` (one YAML file per data type; each file's header explains its fields).
2. Run the build from this directory (the website and profile repos are expected as siblings, e.g. `../ajsteinmetz.github.io`):

   ```bash
   pip install -r requirements.txt   # first time only
   python build.py --pdf
   ```

3. Review and commit the changes in each of the three repos.

`python build.py --check` reports outputs that are out of date without writing anything.

| Output | Source |
|---|---|
| `cv_ajsteinmetz.tex` / `.pdf` | `templates/cv.tex` |
| website `cv.md`, `publications.md`, `talks.md`, `teaching.md` | `templates/web/*.md` |
| website `index.md` (Recent Publications) | `templates/blocks/recent-publications.md` |
| profile `README.md` (Code for Papers) | `templates/blocks/papers.md` |

**Generated files are overwritten on every build: edit `data/` or `templates/`, never the outputs.** In `index.md` and the profile README, only the text between `<!-- BEGIN GENERATED: ... -->` and `<!-- END GENERATED: ... -->` markers is replaced; the rest stays hand-written.

Style conventions (en dashes, HTML entities vs. LaTeX accent macros, `ACT\slash HEBUT`, bolding "Steinmetz, A.", identifier formatting, footnote lettering) are applied by the renderers in `build.py`, so data files hold plain Unicode text with `*italic*` as the only markup.

> **Note on repository layout:** the data and build script live here because the CV is the superset of every other output. If further outputs are added in the future (e.g., a faculty page, NSF biosketch, or the research/teaching statements drawing on `data/`), consider splitting `data/`, `templates/`, and `build.py` into a separate repository (`git subtree split` preserves history) that feeds all outputs, including this CV.
